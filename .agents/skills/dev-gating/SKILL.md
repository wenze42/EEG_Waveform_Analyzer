# 开发门禁（Development Gates）

> 核心理念：AI 说过了，不算；证据过了，才算。

本 Skill 把 LingDoc 实战验证的"两道门"方法论打包成可复用的开发纪律。使用前先阅读仓库根目录的 `AGENTS.md`（硬门槛），以及 `docs/agents/development-rules.md`（详细流程和例外边界）。

## 适用范围

对以下工作使用本 Skill：

- 实现新 Spec 或拆分大任务；
- 修改数据库、权限、跨模块调用、并发、审计或真实适配器；
- 准备、复审或返工相关 PR；
- 判断 PR 是否可以从 Draft 转为 Ready，或是否满足合并条件。

纯文字、换行或单文件机械重命名可以跳过完整矩阵，但仍需说明影响范围并通过现有 CI。

## 人机分工：Agent 默认接管

默认模式是"Agent 做完，人审结果"。**不要把可由仓库、Issue、Spec、CI 或本地环境推导的事实退回给用户确认。**

### Agent 必须主动完成

- 从 Issue、Spec、代码、迁移、OpenAPI、CI 和现有文档推导范围、消费者、验收项和默认参数；
- 创建验收矩阵、测试夹具、合成数据和可复现的本地/staging 依赖；
- 执行单测、HTTP/浏览器集成、真实适配器、迁移、重启读回、失败恢复和并发验证；
- 更新当前 head 的验收报告、健康评分、PR body、Issue 状态和 Draft/Ready 建议；
- 将无法执行的项准确标为 `NOT RUN`、`N/A` 或 `WARNING`，写清事实、影响和解除条件。

### 只有这些情况才向人提问

- 不可从仓库或上下文推断的外部事实：API Key、外部 endpoint、SSO 测试账号；
- 业务方尚未定义的验收阈值、用户可见取舍或不可逆决策；
- 付费、生产写入、外部发布、合并等需要明确授权的动作。

## 门禁状态和例外语义

| 状态 | 含义 | 是否阻塞 Ready |
|------|------|---------------|
| `PASS` | 当前 head 有可复核证据，满足本次交付要求 | ✗ |
| `PASS (follow-up)` | 接受该项不作为阻塞；真实服务验收必须链接到独立 Issue | ✗ |
| `DEFERRED_MANUAL` | 人工前置未完成但代码侧已满足，**必须**带解除条件与跟进票号 `#NNN` | 不阻塞合并，但阻塞 Beta 放行 |
| `N/A` | 验收前提在当前目标中不存在 | ✗ |
| `WARNING` | 环境有限制但等价路径已通过 | ✗ |
| `NOT RUN` / `BLOCKED` | 必需范围内该项未完成 | ✓ 阻塞 |

## 工作流程

### 1. 代码前门：锁定目的地

先确认一个主要 Issue 和一个 Spec，写清楚用户可见结果、范围内/范围外、依赖和真实消费者。

建立验收矩阵。每个 User Story、失败场景和恢复场景至少一行：

- 用户入口；
- 身份、版本、幂等、锁、审计等领域不变量；
- 成功、失败、权限和恢复结果；
- 持久化、迁移、重启读回、并发和无部分写入；
- 测试、CI、运行报告或人工验收证据。

**写代码前**决定：哪个模块拥有真相，哪个事务保护读取/校验/写入/审计，哪些失败时如何零写入和幂等重试。

### 2. 实现门：沿矩阵形成垂直切片

- 每个提交有一个可验证目的；不要把机械清理和业务修复混在一起；
- 先覆盖领域不变量和失败路径，再接上层接口；
- 跨模块、持久化、并发或审计变化必须补真实集成 seam；**直接 store 测试不能替代生产路径证据**；
- 代码、迁移、测试名称使用同一术语（对齐 GLOSSARY.md）。

### 3. 验收门：Agent 闭环完成

Agent 在请求人工审查前完成以下工作：

- 矩阵每一项都有当前 head 的实现位置和证据；
- 定向测试、构建、lint 和相关集成测试的命令及结果已记录；
- PR body 的 SHA、CI 链接和结论都指向当前 head。

只要当前交付范围内的必需项有 `TODO`、`NOT RUN` 或 `BLOCKED`，**保持 Draft**。

### 4. 人审、反馈和合并

人收到的是可审查的结果包：当前 head、矩阵状态、命令和结果、失败证据、健康评分和剩余决策。

评审意见分类：
- **Blocker**：违反 Spec、事务、权限、数据一致性或缺少当前 head 证据 → 必须修复；
- **Required**：本轮应完成的契约、测试或文档同步；
- **Suggestion**：记录为后续 Issue，不阻塞。

**只有在 PR 非 Draft、评审阻断已解决、当前 head 的必需 CI 全部通过时才合并。**

## 交付格式

报告：

1. Issue/Spec 和本次目的地；
2. 验收矩阵中已完成、未运行、阻塞的项目；
3. 当前 head、验证命令和结果；
4. Draft/Ready/合并建议及其理由；
5. 未覆盖风险和后续决策。
